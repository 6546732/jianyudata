# 剑鱼自动导出：每日400条，凌晨03:00

## 使用
打开 START_AUTO.ipynb，依次运行6段：安装依赖、加载代码、配置进度、输入账号密码、连接浏览器、启动调度。
Notebook内已包含全部源码；同目录.py是相同版本的可审查源码，不需要单独运行。
首次运行时间为北京时间 **2026-09-14 03:00**，随后每天03:00。如果首次启动时指定时间已过，会立即续跑，然后按每日03:00调度。
运行最后一段后，保持电脑不休眠、网络和Jupyter内核运行。显示[*]并等待是正常现象。旧Notebook调度器必须先中断，避免重复启动。
这不是关机后运行的系统服务；内核退出后需重新启动并输入密码。

## 导出规则
- 原任务起点2025-01-03，沿用 D:\桌面\data 的真实进度；不重置已用额度。
- 每日累计上限400；全国总量能放入剩余额度时优先整天全国导出，包含全国归属记录。
- 额度不足时读取当天实际可选地区，不要求固定34个；按拼音顺序导出连续省份批次。
- 全省组合少于稳定的全国数量时，按用户确认的全国归属记录规则允许省略差额，并记录在 omitted_national 中。差额归类基于用户对网站的确认，不是对每条内容逐一校验。
- 每批完成继续处理后续日期，直到剩余预算不足或范围完成。
- 部分日期已经分省导出后，继续剩余省份，不改用全国重复导出。
- 单省超过400而未超过800时尚未实现市县拆分，会停止提示 needs_finer_split。
- 账号密码本机隐藏输入，只放内存。需要短信/扫码/滑块时仍需人工完成。
- 订单或下载结果不确定时停止，保留pending；不反复自动提交。未自动下载时仍需从原订单下载。

## 手动上传GitHub
1. 解压上传包，保留 jianyudata_auto400 文件夹结构。
2. 打开目标仓库，Code页选择 Add file → Upload files。
3. 把 jianyudata_auto400 文件夹拖入；确认显示 jianyudata_auto400/START_AUTO.ipynb、README.md和各.py。
4. 填写提交说明，例如“Add daily 400 export with 03:00 scheduler”，点击 Commit changes。
建议先提交到新分支便于检查，确认后合并；也可按你自己的仓库流程提交。
不要上传整个 D:\桌面\data，不要上传账号密码、浏览器登录配置、实际下载文件。网页上传不会代你执行.gitignore规则。
优先上传此包里的未运行Notebook。将来上传运行过的Notebook前，清除输出并检查是否含私人记录。
只上传解压后的文件；直接上传ZIP会让仓库只能下载压缩包，无法方便审查源代码。
