## 规则

- 保留省份拼音顺序。求“最长连续前缀”，不跳过中间省份凑100条。
- 按省份拆分的一批成功下载后，当天立即结束，保存未导出的省份；同一天重新运行也不会继续查询或扣除。第二天从剩余省份继续。不设置20/30条停止阈值。
- 日期全国数据可放入剩余额度就整天处理；否则先核对完整省份组合覆盖全国，再对剩余省份前缀二分查找。34省约需6次二分查询，另有覆盖与最终组合校验。
- 同一天始终复用筛选页面，从“为您筛选到…”读取数量，不为每个省进入订单页。不再每次重新打开网站或逐省查询全部省份条数。
- 切换组合只增删有变化的省份；例如从前17省缩小为前8省，只移除后9省。第一次从“全国”切成省份列表时，仍需按网站UI逐省确认“全省”。“全国”不是34个已选省份标签。
- 运行开始只通过订单预览读取一次实际余额，之后本地扣减。最终订单页再次核对。实际余额更少则缩小预算、回到筛选重新规划；更多也不突破100条自定上限。
- 默认**北京时间每天本程序累计最多100条**，不是每次点击100条。重新运行同一个base不会再获得100条。网站自身800条上限不变。
- 单省超过剩余额度但不超过100条，等待次日；单省101～800条无法装进每天100条上限，返回needs_finer_split，不永久跳过。网站硬限制800条以上仍按原规则记录跳过，通知保留待发送，不自动发送邮件。
- 现金费用非零/不明、选中包不是单日限量包、条数不一致或下载不确定时停止。提交前先写pending，禁止失败后自动再次扣除。

## 状态与文件

沿用原 `D:\桌面\data\range_progress.json`、`batch_state`、`downloads`，不要更换base绕过额度。当前任务从2025-01-03继续；1月1日、1月2日已完成。旧1月2日已保存文件采用两行表头，文件校验已支持该格式。

- waiting_quota：本日预算不足，次日再运行相同入口。
- province_batch_done：省份拆分的一批已保存，当天停止；次日再运行相同入口。
- needs_finer_split：下一个省本身超过100条，需要以后提高测试上限或实现更细地区拆分。
- complete/complete_with_skips：已到本次截止日期，后者存在明确跳过记录。
- pending非空：提交结果或下载待核对，只能恢复原订单，不可删除进度重复扣除。

浏览器若未自动下载，原版仍会打开导出记录等待120秒，由用户点击该笔记录的下载按钮；本次并未承诺把这个未适配的回退分支自动化。
